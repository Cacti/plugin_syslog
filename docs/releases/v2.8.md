# Syslog 2.8: background processing and dedicated-database exports

Historical release, published 2020-03-10. [Current releases](https://github.com/Cacti/plugin_syslog/releases).

Syslog 2.8 restores processing and rule-export behavior that could fail when the working directory or database layout differed from the default.

## Highlights

- Fix background processing when the process starts outside the Cacti installation directory.
- Fix rule export when Syslog uses a database separate from Cacti.
- Correct fields that were not updated following the version change.

## Compatibility and upgrade checks

The [metadata shipped in v2.8](https://github.com/Cacti/plugin_syslog/blob/v2.8/INFO) declares a minimum Cacti version of **1.2.10**. Follow the [documentation for this tag](https://github.com/Cacti/plugin_syslog/blob/v2.8/README.md) for the matching installation and configuration steps.

Before replacing plugin files, back up the plugin/local configuration and its database together. Apply migration instructions only when they match the version you are upgrading from.

1. After upgrading, confirm the scheduled processing command works from its actual working directory.
2. If a dedicated Syslog database is configured, verify a representative rule export uses the intended database.
